# WordPress API Plugin — Plain English Plan

## What Are We Building?

A WordPress plugin that turns your WordPress site into a **headless API backend** for both your React storefront and admin panel. Think of it as: WordPress stores all the data, the plugin exposes it as API endpoints, and React consumes it.

---

## How It Works (Simple Explanation)

```
You (Admin) → WordPress Admin Panel → Data saved in WordPress
                                          ↓
                                     Plugin exposes API
                                          ↓
Customer opens site → React frontend → Calls API → Shows data
```

---

## One File Rules Them All

**Every API endpoint is listed in one single file.** If you want to add, remove, or change any endpoint, you open ONE file — `includes/Core/Routes.php`. That's it.

Here's what it looks like:

```php
// "GET /products" means: when someone visits the products URL, run this code
'GET /products'        => [StoreController::class, 'get_products'],
'GET /products/{slug}' => [StoreController::class, 'get_product'],
'POST /auth/login'     => [AuthController::class, 'login'],
// ... about 90 lines total, one per endpoint
```

---

## What the Plugin Does

### 1. Stores Your Data
Everything lives in WordPress:
- **Products, Categories, Collections** → stored as WordPress Posts
- **Orders, Cart, Wishlist** → stored in custom database tables
- **Settings, Footer, Certifications** → stored in WordPress Settings

### 2. Provides API Endpoints
- **Public endpoints** — anyone can access (product list, blog posts)
- **Customer endpoints** — logged-in users only (cart, wishlist, orders)
- **Admin endpoints** — admin users only (CRUD, dashboard stats)

### 3. Handles Login
- Customers register/login with email + password
- Admins login with WordPress admin credentials
- Both get a JWT token (like a digital ID card) that proves who they are

## Database — What Gets Created

When you activate the plugin, it creates 4 new tables:

| Table | Stores |
|---|---|
| `wp_rh_orders` | Customer orders |
| `wp_rh_order_items` | Products inside each order |
| `wp_rh_cart` | Shopping cart items |
| `wp_rh_wishlist` | Wishlist items |

Products, categories, banners, etc. use WordPress's built-in post system — no extra tables needed.

### How Migration Works
1. Admin clicks "Import All" or selects specific data types
2. Plugin reads JSON from `wp-content/themes/react_template/data/*.json` (you copy the JSON files there)
3. Creates WordPress posts with the right structure
4. Shows progress and results
5. Can be re-run (skips duplicates by checking slugs)

### Migration API Endpoint
```
POST /rh/v1/admin/migrate/{type}    → Migrate one type (e.g., "products")
GET  /rh/v1/admin/migrate/status    → Check what's been imported
DELETE /rh/v1/admin/migrate/{type}  → Clear imported data for re-run
```

## How Login Works (Simple)

```
Customer registers:
  Email + Password → WordPress creates user (subscriber role) → Returns JWT token

Customer logs in:
  Email + Password → WordPress checks credentials → Returns JWT token

Every request after:
  Send token in header → Plugin checks token → Allows access

Admin logs in:
  WordPress admin username + password → Returns JWT token (admin role)
```

## Verification (How to Test)

1. **Install plugin** → Activate in WordPress admin
2. **Register** → `POST /rh/v1/auth/register` with email/password → get token
3. **Login** → `POST /rh/v1/auth/login` → get token
4. **Check products** → `GET /rh/v1/products` → returns `[]` (empty)
5. **Admin login** → `POST /rh/v1/admin/auth/login` with WP admin credentials
6. **Run migration** → Admin panel → Data Migration → Import All
7. **Check products again** → `GET /rh/v1/products` → returns products!
8. **Test storefront** → Set `VITE_USE_MOCK=false` in React → it works with live data
9. **Test admin** → Create/edit/delete products through admin panel
